# 聊天页深度分析模式设计

king 已确认在现有聊天页增加模式切换、连接循环 Agent、使用所选模型并展示完整过程。本设计沿用根目录 PLAN.md 已确认边界。

## 方案与取舍

采用显式模式切换。自动判断是否启动循环会增加不可预期的用量；独立运营页面会重复聊天与历史能力，且超出当前页面范围。

过程跟随助手消息保存有界 JSON 元数据，报告仍作为正文。相较新增任务表，此方案改动较小，能够回看失败、停止和完成结果；不承诺后台执行、断点续跑或跨进程恢复。数据库仅增量加列，迁移前保留本地备份。

API 校验身份、会话及模型，聊天服务创建占位消息并逐事件保存进度，Graph 输出初始计划、步骤开始、步骤完成、重规划和最终报告。报告及完成状态落库后才通知前端完成，避免刷新抢跑。断线由 SSE 取消传播，中止生成并记录已停止。进程异常退出的运行中消息启动时标为中断。

## UI 与事件

沿用暖白、石墨灰、Shopify 绿和本地 IBM Plex 字体。输入区附近展示普通问答/深度分析切换、用量提示；进行中锁定模式和模型，支持停止。助手消息内嵌可折叠过程卡片，历史记录可回看模型、步骤、重新规划和失败。只显示计划和执行摘要，不展示模型隐藏思维链。

前端复用登录、CSRF 和 SSE 解码；普通聊天仍使用原接口，深度分析请求 /api/ops。结束前异常断流不得显示为成功。每次请求使用独立标识隔离旧流，切换会话或离开页面时取消。

## 执行边界

复用现有 LangGraph 循环与只读工具集，不启动 MCP，不开放广告和写工具。Planner、Executor、Replanner、报告生成统一使用服务端验证的所选模型。现有规则优先的执行器和日期参数生成机制保留；不把本次接入宣称为新一代全自主 Agent。
