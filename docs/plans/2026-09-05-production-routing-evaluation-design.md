# 生产规模语义路由评估集设计

## 目标

将现有 48 条回归题、24 条语义题和 12 条独立新增题扩展为可复现、可分层分析的 1500 条评估套件。评估对象仍是语义规划层：输入当前问题和最近对话，输出六类路由及最多四个只读工具。评估过程不执行 Shopify 工具，不访问订单、客户或库存数据。

## 数据集结构

套件拆为五个 JSON 文件。`core_gold` 覆盖 17 个 Shopify 工具、六类路由和典型组合，是人工可以逐条复核的核心集；`paraphrase_noise` 扩展口语、错别字、标点噪声、中英混合和日期说法；`multiturn_context` 覆盖追问、改口、代词、省略和历史诱导；`mixed_rag_shopify` 固定知识资料与实时数据同时出现时的工具选择；`safety_boundary` 覆盖写操作、越权、提示词注入、未接入广告平台和需要澄清的问题。

所有用例由确定性生成器产生并写入固定清单。清单记录套件版本、随机种子、各文件条数和 SHA-256。问题文本和 ID 在整个套件内唯一，标签只能引用当前允许列表内的工具。合成用例用于规模和鲁棒性测试，不冒充真实用户日志。

## 评估流程

评估器读取 `manifest.json` 后顺序合并五个集合，继续通过并发信号量限制真实模型请求。逐题结果保存问题、期望与实际路由、期望与实际工具、错误类别和规划耗时。汇总报告增加路由混淆矩阵、P50/P95/P99 延迟和重复运行一致率，同时保留原有严格准确率及工具 Precision、Recall、F1。

完整 1500 条评估由开发者显式运行并写入 Git 忽略目录。自动化测试只验证生成器可复现、清单摘要正确、标签合法、分布达标，以及评估统计函数在替身结果上的正确性。这样能防止 CI 调用外部模型，也不会接触真实 Shopify 数据。

## 验收标准

- 五个数据文件分别为 300、500、250、200、250 条，总数 1500。
- ID、问题文本全局唯一，历史消息结构合法，工具和路由标签满足规划器约束。
- 17 个 Shopify 工具、六类路由、单工具、多工具、无工具及多轮场景均有覆盖。
- 相同随机种子重复生成得到完全相同的文件摘要。
- 真实模型运行后生成逐题报告；简历只引用实际报告中的可核验结果和指标边界。
