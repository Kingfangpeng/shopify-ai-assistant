# P1 生产化能力与验证

## 本地运行边界

对话、规划、摘要和记忆提取使用本机 Ollama 的 `qwen3.5:27b`，Embedding 使用 `nomic-embed-text:latest`。设置 `LOCAL_LLM_ONLY=true` 后，LLM 工厂只允许 `127.0.0.1`、`localhost` 和 `::1`，任何指向 DeepSeek、OpenAI 或其他外部主机的模型请求都会在建立连接前失败。

FlashRank 模型只在维护命令中下载，在线请求不会临时下载：

```powershell
py -m uv run python -m app.cli prefetch-reranker
```

## Memory

会话使用“当前消息、版本化摘要、长期记忆”三层上下文。模型提取内容只创建 `candidate`，用户在“长期记忆”页面确认后才变成 `active`。同一键的新版本会把旧版本标记为 `superseded`；候选默认 30 天过期。密码、Token、API Key、银行卡和支付信息在候选及手工创建两条路径都会被拒绝。

## 混合检索

Milvus 集合包含 `dense` 和 `sparse` 两个索引。查询时稠密向量与 BM25 各取 20 条，Milvus RRF 融合留 12 条，再由 FlashRank `ms-marco-MultiBERT-L-12` 精排到 5 条。查询包含完整 SKU、型号等精确标识符，且该标识符确实出现在 RRF 首条时，才保留该条作为锚点；普通语义查询完全采用 FlashRank 顺序。所有查询都按 `metadata["user_id"] == user_id` 过滤。结果保留文件名、文档 ID、版本、标题、chunk ID、排序方式和分数；精排不可用时返回 `reranker_unavailable`，并保留 RRF 排序。

知识库重建会先创建影子集合，写入全部仍有效的用户文档并执行冒烟检索；成功后才切换 `shopify_kb_active` 别名。旧集合不会自动删除，可用于回滚。

## 工具参数与 MCP

17 个 Shopify 只读工具统一注册在 `app/agent/tool_registry.py`。模型最多提交 4 个工具调用，只能生成 `comparison`、`status`、`limit`、`top_n` 和 `product_ids` 候选参数。日期、用户、店铺时区、凭据、Provider 和 GraphQL 均由服务端生成。参数完整校验通过后才执行；第一次结构不合格时只允许一次修复。

`AGENT_TOOL_TRANSPORT=local|mcp` 控制传输，默认 `local`。MCP 绑定 `127.0.0.1:8003`，必须通过 `.env` 的 `MCP_SERVICE_TOKEN` 鉴权。客户端在首次调用时完成工具发现与 ToolSpec 目录 hash 校验，带超时、一次有限重试和熔断；MCP 失败会返回明确错误，不会切回本地。

## Prompt 版本

Prompt 文件、语义版本和 hash 位于 `prompts/registry.json` 与 `prompts/registry.lock.json`。普通聊天、SSE 终态、深度分析消息和评估报告会记录内容 hash、工具目录 hash、输出 Schema hash及组合 hash。修改 Prompt 后必须升级版本并更新 lock，否则后端测试失败。

## 评估命令

冻结数据包括 1500 条路由题、300 条候选参数题、500 条检索题及其中 120 条生成题。评估输出在已忽略的 `output/`，不会进入公开仓库。

```powershell
py -m uv run python scripts/evaluate_tool_routing.py --suite tests/fixtures/evaluation/manifest.json --model qwen3.5:27b --concurrency 8 --batch-size 50 --minimum-accuracy 0.98 --output output/tool-routing-local-qwen.json
py -m uv run python scripts/evaluate_tool_parameters.py --model qwen3.5:27b --output output/tool-parameter-evaluation-local-qwen.json
py -m uv run python scripts/evaluate_rag.py --include-generation --generation-concurrency 3 --output output/rag-evaluation-local-qwen.json
```

生成子集会进行 120 次本地 Qwen 推理。新报告明确标记 `local_ollama/qwen3.5:27b`；旧 DeepSeek 报告不能作为本次改造结果。

## 本地验收结果

以下结果来自本机 Ollama、Milvus 2.5.10 与 FlashRank 的完整冻结集，报告位于 Git 忽略的 `output/`：

| 评估 | 规模 | 结果 | 门槛 | 判定 |
|---|---:|---:|---:|---|
| 语义路由 | 1500 | 严格准确率 99.33%，路由准确率 99.73%，请求失败 0 | 严格准确率 ≥98% | 通过 |
| 工具候选参数 | 300 | 字段准确率 100%，非法参数执行 0 次 | ≥98%，0 次 | 通过 |
| RAG 检索（RRF+FlashRank） | 500 | Recall@5 / MRR@10 / NDCG@10 均为 100% | ≥95% / ≥90% / ≥90% | 通过 |
| RAG 权限与延迟 | 500 | 权限泄漏 0，P95 604.59ms | 0，≤1500ms | 通过 |
| RAG 生成 | 120 | 引用准确率 100%，无答案拒答率 100% | 均≥95% | 通过 |

路由报告使用 Prompt `routing@1.1.0`，工具 Precision/Recall/F1 为 99.57%/99.93%/99.75%，P95 规划耗时 18.62 秒。它是本机 27B 模型对冻结合成集的规划层结果，不代表 Shopify 查询、最终回答或线上业务成功率。

## 真实只读端到端验证

- 普通聊天使用本地 `qwen3.5:27b` 规划为 `shopify`，通过 local Provider 调用 `get_orders_summary`，真实来源为 Shopify GraphQL，并记录 `routing@1.1.0`。
- LangGraph 深度分析生成三步计划，按 Planner 明确写出的工具标记先后执行 `get_orders_summary` 与 `get_refund_stats`，再生成报告；验证过程只记录工具名、事件类型和文本长度，不输出店铺经营数值。
- Executor 优先执行步骤中明确列出的注册工具，证据描述中的其他业务名词不会增加工具；Replanner 在剩余步骤仍有明确数据工具时不能提前结束。
